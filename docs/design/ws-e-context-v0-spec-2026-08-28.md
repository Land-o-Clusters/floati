## E2.1 — `floati context status --root ROOT --as NODE [--json]`

Reports, per the node's recorded harness, what context state is actually
observable. With E1's findings, every row today is a **typed absence**:
`remaining context: not exposed by <harness>` — each absence CITES the E1
receipt (evidence path + SHA) that measured it. The absence table is DERIVED
from a shipped, versioned dataset generated from E1's receipts — never
hardcoded prose per call site (a closed set must contain itself; an
enumeration that cannot be derived must be counted). If a future harness
exposes a number, the row carries the harness's own figure with a MEASURED
stamp and names the API it came from; **no ESTIMATE row exists in v0 because
no estimator exists — a fraction may not be drawn where completion cannot be
measured** (the progress-indicator law).

## E2.2 — `floati context turnover --root ROOT --as NODE [--json]`

The turnover ritual, productized as a PROJECTION (prints, never executes):
compose the already-landed pieces in order —

1. the node's **teardown projection** (D3) — what to flush and retain;
2. a **state-flush receipt** step (D5, metadata-only) — the hinge proving the
   state file moved after the flush instruction;
3. the node's **boot projection** (D3) with role provenance (D1/D2) — the
   ported-context boot prompt for the successor session.

Output is the ordered ritual with each step's existing verb spelled exactly
(the managed-send lesson: a seat's instructions carry its exact verb shapes).
It claims **turnover**, never "automatic context management" — the word
"automatic" is banned from this surface until a harness exposes enough to
automate against.
