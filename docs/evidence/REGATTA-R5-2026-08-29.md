## Mechanism and Floati expression

Kitty's primary protocol defines a screen-local enhancement stack: push with
`CSI > flags u` and pop with `CSI < number u`; flag 1 disambiguates escape
codes. It also requires the pop before leaving the alternate screen. Source:
[Kitty keyboard protocol, progressive enhancement](https://sw.kovidgoyal.net/kitty/keyboard-protocol/#progressive-enhancement).

Floati's expression is deliberately smaller than the quarry:

- `floati/tui_protocol.py` owns one stdlib-only primitive:
  `kitty_keyboard_mode(True) == ESC [ > 1 u` and the exact reverse
  `kitty_keyboard_mode(False) == ESC [ < u`.
- The persistent input decoder now frames a complete bounded CSI event instead
  of assuming every CSI is three bytes. Split/coalesced Kitty modified arrows
  and `CSI 27 u` Escape become the same semantic keys used by the existing
  keyboard path. Modified text keys are not widened into ordinary actions.
- Board and Live Map push the mode only when the per-endpoint R3 capability
  receipt says `kitty_keyboard` is both `MEASURED` and `supported`. TERM-brand
  inference cannot enable it.
- Both surfaces pop the stack inside guarded cleanup before leaving alternate
  screen mode, including on a primary exception. Mouse tracking keeps its
  keyboard twin and exact reverse.
- Every changed presentation remains inside the existing DEC-2026 transaction.
  The tests observe exactly two frames for initial paint plus one real selection
  change while two no-op events emit no frame. The existing R1 idle test also
  observes one initial frame, one render, one model load, and three blocking
  `None` deadlines for an otherwise idle Live Map.

This row adds no timer, animation clock, visible word, palette branch, or
renderer mutation. Board retains its established input/model polling ceiling;
R5 adds zero ambient presentation work.
