## Graphics laws proved

1. Five activity buckets are ordinal event-sequence testimony. Only exact
   records already held by a surface contribute; a record names a node at most
   once, substrings never count, and absence is five measured zeros.
2. `⣀⣠⣤⣶⣿` is the shared Board, Live Map, and interactive replay
   expression. Removing SGR from 256- or 16-color output yields monochrome
   exactly; color carries no bucket value.
3. Pixel overlays require `kitty_graphics=supported` plus `MEASURED` in the
   current R3-CAP receipt. Unsupported, unknown, DERIVED, ESTIMATE, malformed,
   and monochrome policy paths emit no pixel bytes and no warning.
4. Each 20-by-8 activity PNG is deterministic, bounded to 1024 bytes, and uses
   only Floati orange, harbor dark, and transparent RGBA. The same five samples
   drive its columns and the braille twin below it.
5. Stable target-derived image IDs are de-collided within the bounded 128-image
   frame. Only exact rendered braille coordinates receive overlays; resize,
   clipping, and target removal delete stale placements.
6. Text, changed image placement, and cursor commands share one DEC-2026 frame.
   Board and Live Map remember every image ID actually transmitted and delete
   all of them on exit even when termios restoration fails.
7. Board and Live Map upgrade when their measured receipt permits. Replay
   renders the braille law but its output-only API emits no graphics protocol
   and makes no capability guess. Static README/capture replay paths remain on
   their approved R2 renderer and byte-identical capture bank.
8. Idle presentation remains dirty/event driven. The existing pseudo-terminal
   zero-idle-output bank passes unchanged; overlay plans emit no bytes when
   text, geometry, samples, and capability receipt are unchanged.
