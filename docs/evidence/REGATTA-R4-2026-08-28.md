## Behavior proved

- Every fresh request focuses stable option id `refuse-once`; resolving a broad
  grant never changes the next request's initial focus.
- `Esc` refuses immediately from any focus. Digits and arrows only move the
  explicit selection; `Enter` alone commits it.
- Mouse input must click the same request-scoped option twice inside the fixed
  300 ms window. Any session-or-broader option returns the typed
  `approval_mouse_broad_forbidden` note and remains pending.
- Each decision receipt carries the stable option id, option scope, acting
  session, and SHA-256 of the exact JSON record body rendered to the human.
  The test independently recomputes that digest and verifies the receipt sink
  append. Changed record bytes refuse with `approval_panel_stale` before the
  queue advances.
- Concurrent requests remain FIFO. Enqueue neither replaces the displayed
  record nor changes its focused option. Composer text is stashed on the
  empty-to-nonempty transition and restored only when the queue drains.
- Environment and flag sweeps cannot resolve a panel; the only shipping seam
  returns `approval_human_act_required` for non-human resolution attempts.
- Color, monochrome, and `NO_COLOR` surfaces contain the complete exact-record
  panel and unmistakable `>` focus glyph. Stripping SGR from the color capture
  yields the monochrome bytes exactly.
