## Capability laws proved

1. DA1 is the barrier. The only first query byte is `CSI c`; the DECRQM,
   Kitty, and XTGETTCAP batch follows an exact DA1 response. Keystrokes around
   coalesced replies survive in their original order.
2. Six facts remain separate: synchronized output 2026, SGR mouse 1006,
   SGR-Pixels 1016, Kitty graphics, Kitty keyboard, and RGB. One successful
   response cannot cross-enable another capability.
3. Every fact carries state, stamp, source, and evidence digest. Exact replies
   are MEASURED. TERM/COLORTERM timeout testimony is DERIVED; brand/tmux
   timeout testimony is ESTIMATE. Only `supported` plus `MEASURED` enables.
4. Timeout is typed `unknown`. It is never rewritten to `unsupported` or a
   false capability claim, even when a heuristic or brand prior exists.
5. The receipt is per direct endpoint. A non-empty `TMUX` identity wins over
   outer-terminal environment testimony; its raw value is digest-bound and
   never printed. DA2 identifies and does not negotiate.
6. `NO_COLOR` is excluded from capability truth. Adding it to an otherwise
   identical environment produces byte-identical receipt JSON.
7. Non-TTY stdout returns a fully unknown receipt and emits exactly zero DA1,
   Kitty, DECRQM, XTGETTCAP, or other probe bytes.
8. Response parsing is bounded at 4096 bytes and returns at most the existing
   64-byte input ceiling after an oversized hostile buffer. Partial response
   frames remain intact for the caller's next read.

Board and Live Harbor Map each append exactly one byte-identical per-endpoint
receipt through their optional sink. Existing plain/non-TTY paths return
before the collector and remain byte-identical.
